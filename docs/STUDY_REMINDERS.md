# Study reminders — Resend Free

Reminders use the existing free Resend account and verified `mpkacademy.com` sender, with a **separate sending-only API key**. Authentication keeps its existing Supabase SMTP credential and configuration. Nothing in this implementation changes billing, subscribes to a paid plan, or upgrades the account.

Resend Free currently allows 100 messages/day and 3,000/month, shared across API keys and SMTP. Reminder reservations are capped at **50/day and 1,500/month (UTC)**. A reservation includes uncertain delivery outcomes. At fewer than 50 users and three messages per rolling seven days, the expected reminder volume is below 150/week. Check the [current provider limits](https://resend.com/docs/knowledge-base/account-quotas-and-limits) when changing capacity.

## Behavior

Verified accounts get enabled preferences automatically, including existing accounts. A visible signed-in page updates latest presence at most every ten minutes and detects the browser's IANA time zone unless the learner chose a manual override. The fallback is America/Toronto. Inactivity uses the latest sign-in, presence or completed learning activity. Only that latest presence is stored, not browsing history.

The worker considers one message per learner between 18:00 and 20:00 local time, with a scheduler tick every 15 minutes. It waits 24 hours after signup, skips users active in the last 30 minutes, enforces 48-hour spacing, three reservations per rolling seven days, and one per local date. After 30 days of inactivity the rolling limit drops to one. A completed learning activity that local day suppresses study nudges.

Priority is past exam date (one update request, then pause until the date changes), exam today (skip), exam in 1–14 days, weekly-plan deficit, then 72-hour inactivity. Missing dates generate neither countdowns nor weekly targets. Weekly counts and expected progress use UTC weeks; exam and delivery calendars use the saved time zone. Templates reuse the study-plan calculation and the same reading/listening readiness average. English/French messages follow the saved language and link to accessible setup, assessment, results or dashboard pages.

`/email-preferences` is available before onboarding/access gates and is an exact allowed post-login return path. Settings includes the same controls. Signed unsubscribe GETs only show confirmation; POSTs opt out and cancel outstanding sends, including mailbox one-click POSTs. Re-enabling rotates the token version. A request already in flight to Resend cannot be recalled; subsequent attempts recheck consent and eligibility.

## Delivery safety and data

The private database ledger freezes message content at the first claim. Claims serialize through a quota-control row and the learner preference row. Overlapping workers cannot own the same live lease or exceed budget. Immediately before the provider call, the worker rechecks current eligibility. Retry claims keep the exact payload and `study-reminder/<delivery-id>` idempotency key; Resend retains keys for 24 hours, while this worker expires messages after two hours or at 20:00 local time. It never replays yesterday's backlog.

A network timeout remains uncertain, counts toward all limits, and retries with the same key. Provider `daily_quota_exceeded` / `monthly_quota_exceeded` responses pause reminders until the UTC reset. Request-rate errors respect Retry-After. Authentication errors pause for 24 hours and require operator attention. Budget deferral favors learners with the oldest reminder attempt. At least 250 ms separates successful provider requests, leaving rate-limit headroom for account mail.

Webhook signatures are verified against the unmodified request body, including timestamp tolerance. Event IDs deduplicate processing. Bounces, complaints and provider suppression events suppress the recipient address; late delivery events cannot undo suppression. Signed webhook delivery tags permit correlation even if the webhook beats the API response. Keep the webhook active even when sending is paused.

Delivery bodies/addresses and webhook event IDs are private and deleted after 30 days. Aggregate quota buckets contain no identities and survive cleanup so a 31-day month remains correctly capped. Preferences, latest presence, exam-date notice state and address suppression records survive delivery cleanup. No learner can read another user's preferences or invoke service-only worker RPCs. `/admin` shows counts, budget reservations, pause reasons and recent failures without message content.

## Configuration and rollout

1. Apply `20261126000100_study_reminders.sql` to the explicitly selected environment. The CLI's linked project is normally **staging** (`czbynijgpkflnntgoqgj`); production is `uhbuvskmiojqjegpuuln`. Do not rely on the linked default. The migration leaves `private.study_reminder_control.enabled=false`.
2. Deploy with `STUDY_REMINDERS_ENABLED=false`. Create a dedicated **Sending access** key restricted to the verified domain in the existing **Free** Resend account. Store it as server-only `RESEND_REMINDER_API_KEY`. Never reuse/export the authentication SMTP key.
3. Set `STUDY_REMINDER_FROM=MPK Academy <no-reply@mpkacademy.com>`, HTTPS `NEXT_PUBLIC_APP_URL`, a random 32+ character `STUDY_REMINDER_UNSUBSCRIBE_SECRET`, and the existing 32+ character `JOBS_SECRET`. Keep the unsubscribe signing secret stable so old links keep working. Never commit or paste credentials into logs.
4. In Resend configure `POST https://<app>/api/webhooks/resend` for `email.sent`, `email.delivered`, `email.delivery_delayed`, `email.bounced`, `email.complained`, `email.failed` and `email.suppressed`. Store its signing secret as `RESEND_REMINDER_WEBHOOK_SECRET`. Verify the events supported by the current dashboard. Disable open/click tracking for reminder mail in the sender domain settings unless separately disclosed.
5. Add Supabase Vault `mpk_study_reminders_url=https://<app>/api/jobs/study-reminders`. `mpk_jobs_secret` must match the application's existing JOBS_SECRET. The migration creates `mpk-study-reminders` on `*/15 * * * *`; it cleans logs even while sending is disabled and only calls the app when the database flag is enabled. No AI key is required.
6. POST to the job route with the Bearer JOBS_SECRET and JSON `{"dryRun":true,"previewOutsideWindow":true}`. Inspect authorized recipient previews, English/French text, links, date logic and exclusion cases. Previews ignore the delivery-hour window only, and **never send**. Treat previews as private account data. A normal empty JSON body respects the delivery window and both sending flags.
7. Set `STUDY_REMINDER_ALLOWED_EMAILS` to controlled inboxes. Enable the app flag and database flag (`update private.study_reminder_control set enabled=true where id;`). Use eligible verified test accounts with no activity in the past 30 minutes. To test before the local delivery window, the protected job accepts `{"controlledRecipient":"your-controlled-inbox@example.com"}`. This requires an exact match in the deployment allowlist and selects only that recipient. It waives only the time-of-day check: consent, account age, activity, frequency, quotas, immutable retries and unsubscribe still apply. The test counts as a reminder reservation. Migration `20261126000200` adds the service-only database argument. Confirm receipt, webhook delivery status, GET confirmation and POST unsubscribe. Test bounce/complaint fixtures only with controlled accounts/provider test addresses. Check `/admin` counters.
8. After the controlled test succeeds, remove the allowlist and redeploy. Check the next scheduled tick and provider usage; authentication and reminder keys share the free quota. No upgrade is needed or performed.

Stop sends immediately with the database enabled flag; keep cleanup and webhook processing active. Keep the application flag off as an additional deployment guard. Never force resend an uncertain delivery with a new idempotency key. Do not clear ledger rows to bypass limits. Resolve bounced addresses with the learner before removing a suppression.
